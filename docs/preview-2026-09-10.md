# Preview 2026-09-10

The same neural fixes are included in both packages. The normal build supports D3D11/D3D12;
the Vulkan build adds the experimental Vulkan transport and device-creation hook. Install only
one `dlss5-neural.addon64`. `src/neural/build_config.h` identifies the branch's default variant.

## Runtime and upgrade

Close the game, back up the existing add-on and INI, and replace the add-on with the selected
package. Keep your INI. Runtime and weights are supplied separately and are not in these packages.
The normal branch now requires the same v0.2.17 runtime as the Vulkan branch; v0.2.14 is refused.

SHA-256 of the required files:

```text
ddd82d313aa74c2e7602d17dfb7e7cd90cca9bfc0306f581684d35d75d1b350b  dlssnr_amd_pass1.dll
6bf8dc931ef3ccffe18c82de26ab374156e7f19539ffcf8eabaa25dca5cf15ab  dlssnr_on_amd_weights.bin
```

`tools/extract_runtime.py` and `tools/patch_runtime.py` reproduce the expected runtime from
the matching upstream installer without executing it. See the README for the procedure.

For an SDR image, set `Encoding=0`, `Tonemap=-1` and restart. Automatic tonemapping now resolves
to off for this input even though its transport texture is FP16. An explicit override remains
available. This change does not establish a correct HDR/PQ contract for every game.

The add-on starts disabled unless the existing INI explicitly sets StartOn. Use Ctrl+End or the
overlay to enable it. The package contains no replacement INI, so personal tuning is preserved.

## Changes

- Inline multipass submits each intermediate pass and waits for both its GPU commands and its
  HIP worker to finish before overwriting shared runtime tuning. The old batch path could make
  every pass consume the last profile. A GPU resource barrier alone could not fix that.
- `SerialPasses=1` is the default in inline mode. `SerialPasses=0` is a diagnostic reproduction
  of the previous behavior, not the recommended setting. Async retains the old handoff.
- The write through an alleged abort pointer at 0x8d808 was removed. In v0.2.17 this is a pair
  of watchdog job counters; treating them as a pointer crashed a full-resolution run after a timeout.
- Optional captures save matched network input and runtime output, with dimensions and encoding.
  Readback waits now check GPU completion before mapping.

## Validation

The GPU fixture uses a saved 1920x1080 NFS 2015 garage frame on an RX 9070 XT. Temporal history
and guides were disabled to compare deterministic outputs. It includes the production neural
implementation and uses the private-D3D12 submission helper used by the bridge.

| Check | Result |
|---|---|
| Two serial passes: first-pass Tone 1 versus 0 | Different outputs; RGB MAE approximately 0.0132195, maximum 0.3338623 |
| Same serial profile in separate processes | Exactly identical FP16 outputs |
| Old batch Tone 1→0 versus serial Tone 0→0 | Exactly identical, reproducing loss of the first-pass setting |
| Three serial passes with Structure taper | 120 frames / 360 jobs completed; final image matched the earlier shorter run |
| Automatic SDR tonemapping versus explicit off | Exactly identical outputs in the controlled SDR comparison |

The first regression attempt captured a legacy-mode frame whose first pass hit the runtime's
watchdog and kept its input. It was not a completed two-pass inference. The regression runner now
checks the final frame's watchdog job, preserves rejected attempts, and retries at most three times.
The subsequent four-case run passed all assertions. Timeouts are not hidden or fixed by this check.

Approximate steady pipeline times from the saved NFS frame: two passes at full scale ~55 ms;
three ~83 ms; two at 0.75 scale ~34 ms. These are isolated pipeline measurements, not in-game FPS.
The runtime still has occasional ~250–300 ms spikes.

The earlier SDR/capture/crash-fix build ran in NFS. The final serial build has not yet been
retested in live gameplay or on the native D3D12/Vulkan presentation paths. Static-frame tests
do not validate ghosting, disocclusion, driving, HUD behavior or temporal quality. The runtime
still shares temporal state between neural passes.

## Diagnostic tools

With `Diagnostics=1` in `[dlss5]`, Ctrl+Home reloads the INI and Ctrl+PageDown requests a matched
capture from the foreground game. Files are written to `dlss5-captures` beside the executable.
The runtime image includes its internal residual application; it is not a raw neural tensor
or the final guarded composition. Keep diagnostics off during ordinary performance comparisons.

```powershell
# Requires Python with numpy and Pillow for the capture viewer.
python tools/capture_pair.py path/to/frame-123-456.txt

# Build the isolated GPU fixture; requires the same runtime and an AMD GPU to run.
./build.ps1 -Target framecheck -Exe
python tools/pass_profile_check.py --exe build/dlss5-framecheck.exe `
  --runtime-dir path/to/runtime --input path/to/frame.ppm --output path/to/new-results
```

The output directory must be new. The runner retains its input/output buffers, logs and timings.
Do not treat API success or a moving job counter alone as evidence of a completed inference.

## Upscaling status

FSR 2/3/4 is not included. The intended target remains games without native upscaling support.
Research is considering NR at reduced resolution followed by an AMD FSR backend, with captured
or estimated temporal inputs. Installing OptiScaler alone does not provide that missing input.
